> **帮年轻人对抗冲动消费的网站**：用户把想买的东西提交为一笔“消费审批”，由 AI 与全网清醒网友/密友共同把关投票，核心是给冲动消费加一个冷静期。  
> **核心升级**：
> 1. **全站品牌更名**：全站显示名称统一为“省思袋 👝”，寓意“省钱、三思而后行”。
> 2. **个人专属累计拦截金额**：去掉全站数字，首页与“我的”页严格只计算当前用户自己发布的、最终结果为“不买”的单子累计金额，真切感受自己省下的每一分钱。
> 3. **多媒体上传与预计使用时间弹窗**：支持上传截图、照片或视频并在提交前预览；提交前必须在弹窗中选择或自定义“预计使用多长时间”（如：不到1个月、1-3个月、3-6个月、6-12个月、1年以上或自定义数字与单位）。

> 5. **个性化资料与 MBTI 把关**：首次进入弹窗设置性别、MBTI、星座，支持在个人主页修改；发布审批时支持指定“希望哪些MBTI的人来给建议”。
> 6. **好物分享专区**：全新独立的“好物分享”列表，支持分享好物名称、推荐理由、价格与图片，与审批流互为补充。

## 🌟 核心特性与亮点

1. **多人真联网（Supabase Realtime）**
   - 告别单机 localStorage 业务存储，所有审批单、投票、讨论、好物分享实时入库。
   - 任何人在任何设备投票或发单，另一台设备毫秒级无感更新，双色投票柱状图动态变化！
2. **真实 GLM 推理（Netlify Function 服务端中转）**
   - API Key 只从服务端环境变量 `GLM_API_KEY` 或用户本机自填的临时 Key 读取，前端产物里不含任何 `VITE_` 形式的模型密钥。
   - 后端带 12 秒超时与脱敏诊断，返回 `source` 字段区分 `glm` / `fallback`；失败自动回退规则引擎，不报错、不空白。
   - 详情页首次打开会在后台静默补刷一次真实 GLM 结论（每会话每单只试一次，不烧额度）；卡片上明确显示引擎来源。
   - 支持“换个角度再评一次”，具备同一用户 1 分钟（60s）防刷限制。
3. **AI 权重折算机制（平票判驳回）**
   - 发起人可自定义 AI 建议权重（0%–100%，默认 20%）：
     - 权重为 0% 时：AI 建议仅供参考，折算 0 票；
     - 权重超过 50% 时：页面醒目提示 AI 将占主导地位；
     - 折算规则：$\text{AI 票数} = \text{round}(\text{权重\%} \times \text{目标人数})$；
     - AI 建议买记为支持票、建议不买记为劝退票、再想想记 0 票；
     - 最终结果 = 人类有效票 + AI 折算票，得票多者胜，平票判不买（贯彻冷静期守护钱包原则）。
4. **自定义冷静期时长与目标人数**
   - 冷静期：12 小时 / 24 小时（默认）/ 48 小时 / 72 小时 / 自定义（1–168 小时）。
   - 目标人数：5 / 10 / 15 / 20 / 30 / 自定义（3–50 人）。
   - 达到目标人数或冷静期到期自动结算，无需死等凑齐人数。
5. **严防发起人自刷票**
   - 前端识别发起人并禁用投票区，提示“你是发起人，不能给自己投票”；
   - PostgreSQL 数据库触发器在写入时进行校验，物理拒绝发起人给自己刷票。
6. **移动端触感反馈（Haptic Vibration）**
   - 投票成功轻震 15ms，发起提交震 30ms，关键按键轻震 10ms；
   - 仅在主动手势中触发，iOS 网页安全降级，顶部导航栏支持随时开关。

## 🤖 接入智谱 GLM 真实大模型

默认模型为 `glm-4.7-flash`（智谱官方免费文本模型，OpenAI 兼容端点）。推理发生在
`netlify/functions/ai-recommend.js`，前端只调 `/api/ai-recommend`（由 `netlify.toml` 重定向到 Function）。

### 三种配置方式

| 方式 | 适用场景 | 操作 |
| --- | --- | --- |
| **A. 服务端环境变量（推荐，正式上线）** | 竞赛 / 生产环境 | Netlify 后台 → Site configuration → Environment variables → 新增 `GLM_API_KEY`，保存后重新部署 |
| **B. 站内自填（无需重新部署，最快验证）** | 临时演示、部署额度暂停时 | 网站「我的」→ 配置弹窗 → 填入 GLM API Key → 点「测试 GLM 是否接通」 |
| **C. 本地 `.env`** | 本地 `netlify dev` 调试 | 复制 `.env.example` 为 `.env` 并填 `GLM_API_KEY`；`.env` 已被 `.gitignore` 忽略 |

### 关键约束

- **绝不能**把 Key 写成 `VITE_GLM_API_KEY`：带 `VITE_` 前缀的变量会被 Vite 打进前端 JS，等于公开密钥。
- Key 优先级：`GLM_API_KEY` > `AI_API_KEY` > `DEEPSEEK_API_KEY` > `OPENAI_API_KEY` > 浏览器自填 Key。
- 换用其他 OpenAI 兼容服务时，需同时设置 `AI_BASE_URL` 与 `AI_MODEL`（例如 GLM Coding Plan 有专属端点）。
- 调用失败（401 / 429 / 超时 / 返回非法 JSON）一律回落规则引擎，并把脱敏后的原因显示在 AI 卡片与配置弹窗里。

### 怎么确认真的接上了

1. 配置弹窗点「测试 GLM 是否接通」，看到 `✅ GLM 已接通（glm-4.7-flash）` 即成功；
2. 打开任意审批详情页，AI 卡片徽章变为绿色 **「GLM 实时推理 · glm-4.7-flash」**；
3. 灰色 **「本地规则引擎 · 尚未接入大模型」** 说明仍在回退，旁边会给出具体原因。

### 为什么以前“接了却没反应”

旧版在 `CreatePage` 发布审批单时用前端规则引擎直接写死了 `ai_verdict`，`fetchAiRecommendation`
又有缓存短路，导致详情页根本不会请求后端；后端即使失败也恒返回 `configured: true`，真假 AI 完全无法区分。
现已修复：缓存只在「已有真 GLM 结果」或「本会话已自动补刷过」时生效，且后端统一返回 `source` 字段。

### 本地开发

`npm run dev` 会把 `/api/ai-recommend` 代理到已部署的线上 Function（**只代理这一个路径**，
不会把 `/api/sync-data` 的写操作同步到线上数据）。若要调试本地 Function，改用 `npx netlify dev`，
并把 `vite.config.js` 里的代理 `target` 改成 `http://localhost:8888`。
